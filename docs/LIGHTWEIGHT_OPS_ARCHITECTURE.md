# 单项目轻量 OPS 架构整改说明

## 定位

当前系统面向单项目、小团队维护场景，采用轻量化单体架构：

- 平台本身负责资产配置、状态诊断、巡检执行、台账报表、报告中心、MCP/AI 辅助分析。
- 不启用服务器侧 Agent 运行时，不引入 Agent 注册、心跳、任务队列、升级、离线告警等复杂分布式机制。
- 巡检仍支持服务器基础巡检、项目巡检和项目综合巡检，但执行方式为平台本地/SSH 只读命令。
- AI 仅负责摘要、解释、归因建议、整改建议和报告生成，不自动执行高风险动作。

## 本次整改内容

1. 弱化 Agent：
   - `ops.agent.*` MCP 工具保留代码占位，但默认禁用，不再出现在常规工具目录中。
   - MCP Resources 移除 `ops://agents`，避免自然语言工作流误依赖未启用的 Agent 状态。
   - 项目健康 AI Workflow 不再调用 `ops.agent.get_status`。

2. 简化前端导航：
   - `AI 能力` 独立菜单隐藏，保留路由备用。
   - `AI 工具` 改为 `MCP / AI`，作为轻量 AI 辅助入口。
   - `系统` 改为 `配置中心`，强调数据库配置与当前项目配置。
   - `巡检中心` 文案改为单项目轻量巡检、台账与报告。

3. 简化巡检入口：
   - 不再单独突出“综合巡检”页签。
   - 项目巡检页内提供“项目综合巡检并生成报告”按钮。
   - 巡检中心说明改为“平台本地/SSH 只读检查 + 台账报表 + AI 辅助分析”。

4. 能力策略：
   - `capability_server` 默认配置增加：
     - `ops_mode = lightweight_single_project`
     - `agent_runtime_enabled = false`

## 推荐使用方式

- 日常运维：进入巡检中心执行服务器巡检或项目巡检。
- 项目安全判断：在项目巡检页点击“项目综合巡检并生成报告”。
- 报告沉淀：在台账报表中生成每日台账、每周报表、月度报告。
- AI 辅助：通过 MCP / AI 工具生成巡检摘要、项目健康简报、风险分流、月度报告。

## 后续原则

单项目、小团队场景下，不优先开发以下复杂能力：

- Agent 注册 / 心跳 / 升级
- 分布式 agent_task 任务队列
- 多节点调度
- 自动化封禁、重启、删除、修改配置
- AI 自动执行高风险操作

优先打磨：

- 巡检规则准确性
- Shell 命令只读安全
- 巡检结果可读性
- 台账与报告质量
- 配置中心数据库化
- API 错误可见性
